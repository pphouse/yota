# yota

AIのキャラクターと物語を紡ぐWebアプリ（PWA）。最初の1,000人を集めるためのMVPです。

- **すぐ返ってくる**：最初の文字はすぐ出し、そのあとは人が書くくらいの速さ（約50文字/秒、句読点で少し間をあける）で見せる。文章AIが長文を一瞬で返しても、貯めておいて少しずつ出す（`src/lib/typewriter.ts`）。表示中の返答をタップすると残りを一気に出せる。
- **返事の候補**：最初の一言には作品ごとの候補、そのあとはキャラが返すたびに、場面に合った候補を3つ文章AIに作らせて出す（`src/lib/suggest.ts`）。
- **2つの遊び方**：「あなたが主人公」（夢小説型）と「ふたりを見守る」（自分は登場しない型）。
- **物語に入りこむ**：最初に自分の名前を決め（ホームの右上からあとで変えられる）、主人公モードではキャラも地の文もその名前で呼ぶ。返答は、吹き出しの中に斜体の動作（`*…*`）、吹き出しの外に周りの情景（`>` で始まる行）を出す。会話の最初には作品ごとのプロローグを情景として出す。
- **作品の見つけやすさ**：公開後に追加した作品には21日間 NEW を付ける（`characters.ts` の `addedAt`）。ホームの「あなたにおすすめ」は、その人が遊んだ作品とカテゴリ・タグが近い作品を、理由（「〇〇の物語を遊んだあなたに」）つきで出す（`src/lib/recommend.ts`）。まだ遊んでいない人には「はじめての方におすすめ」を出す。人気の数字は、実際の数が十分にたまるまで出さない（水増しや予測の数字は出さない）。
- **キャラの MBTI と性格パラメーター**：全キャラに MBTI と、甘さ・一途・独占欲・包容力・ツンデレ・ミステリアスの6つ（0〜100）を付け、カードと紹介ページ（レーダーチャート）に出す。パラメーターは、70以上の項目を「強く出る傾向」、30以下を「弱い傾向」の振る舞いの指示に直してプロンプトに入れる（`prompt.ts` の `describeStats`。数字のままだと台詞で口に出すため）。独占欲が強くても、責める・縛る・脅すことはしないと必ず添える。
- **作品の紹介ページ**（`/plot/[plotId]`）：表紙・紹介文・あなたの役・登場人物のプロフィール（見た目・性格・好き嫌い・口癖・一人称／二人称・好きになったら）を見せてから始める。
- **名場面カード**：返答の一節を画像カードにして、Xなどに共有できる。画像生成AIは使わないので原価ゼロ。
- **広告なし**。
- **安全**：年齢確認、未成年の表現制限と1日3時間の上限、入力と出力の安全判定、つらい気持ちのサインへの案内。

## 動かし方

```bash
npm install
cp .env.example .env.local   # キーを入れなければダミー応答で動きます
npm run dev                  # http://localhost:3000
```

テストと検査：

```bash
npm test          # ユニットテスト（vitest）
npm run lint
npm run build
```

## 文章AIの設定

`.env.local` にどれか1つのキーを入れると、自動でそれを使います（`LLM_PROVIDER` で明示も可）。

| 提供元 | 必要な変数 | 既定モデル |
| --- | --- | --- |
| Anthropic | `ANTHROPIC_API_KEY` | fast: `claude-haiku-5-5` / quality: `claude-sonnet-5-5` |
| OpenAI（互換API含む） | `OPENAI_API_KEY`, `OPENAI_MODEL_FAST` | なし（必ず指定） |
| Cerebras（OpenAI互換） | 上の2つ＋`OPENAI_BASE_URL`, `OPENAI_REASONING_EFFORT` | 下を参照 |
| Gemini | `GEMINI_API_KEY`, `GEMINI_MODEL_FAST` | なし（必ず指定） |

MVPでは全員 `fast` を使います。`quality` は有料化のときに使う想定です。

### 今使っている設定：Cerebras の qwen-3.8-27b

```bash
LLM_PROVIDER=openai
OPENAI_API_KEY=csk-...                       # Cerebras のキー
OPENAI_BASE_URL=https://api.cerebras.ai/v1
OPENAI_MODEL_FAST=qwen-3.8-27b
OPENAI_REASONING_EFFORT=medium
```

- ユーザー像5人（夢女子2・腐女子2・会話が苦手な初心者1）になりきった Claude に、4ラウンド遊ばせて評価し、プロンプトを直した（2026-10-25）。噛み合い・キャラらしさ・日本語・返しやすさ・ときめき・展開・候補ボタンの7項目（5点満点）で、同じ10作品の平均は 2.94 → 3.62 → 3.83。
- gpt-oss-120b より日本語が自然で、キャラの口調も保ちやすい。一方で、他の言語の文字が混ざったり（作り直す。`japanese.ts`）、返答をまるごと推論の側に書いて本文が空になったり（もう一度流す。`chat.ts`）することがある。
- 返答の長さはプロンプトで指定している（主人公モード80〜180字、主人公モードで二人いる作品は100〜200字、見守りモード120〜220字。地の文は2〜3つ、情景の行は1つまで）。動作と情景で場面が浮かぶ長さにしつつ、読む負担が大きくなりすぎないようにしている。
- 推論モデルなので、推論の分も `max_completion_tokens` の枠を使います。`openai.ts` が推論の量に応じた余裕（low +3000、medium +6000、high +10000）を自動で足します。推論の途中経過（`delta.reasoning`）は画面に出さず、本文だけを流します。
- `medium` にしているのは、`none`（推論なし）だと最初の文字まで0.2〜0.4秒と速いものの、見守りで片方しか喋らなくなるなど品質が下がったため（7項目の平均 3.11 対 medium 3.40）。速さの差は体感ではほぼ分からなかった。
- 返事の候補は短いので、考える量を別に `OPENAI_SUGGEST_REASONING_EFFORT` で減らせます（既定は `low`）。`none` にすると速くなりますが、評価では候補の日本語や口調が崩れやすかったため、`low` のままにしています。
- `OPENAI_REASONING_EFFORT` は推論モデルにだけ設定します（推論しないモデルに送るとエラーになります）。

### gpt-oss-120b に戻す場合

```bash
OPENAI_MODEL_FAST=gpt-oss-120b   # ほかは上と同じ
```

- 最初の文字まで約0.3秒と速いが、日本語の言い回しが不自然になりやすい。`low` だとキャラ設定や「同じことを繰り返さない」などの指示が守られにくかったので、`medium` で使う。`OPENAI_SUGGEST_REASONING_EFFORT=none` は受け付けない。

Anthropic と Gemini の実際のAPIでの動作確認はまだしていません。

## iOS / Android アプリ

Capacitor で、本番の yotachat.app を読み込むアプリにしています。共有・通知・戻るボタン・外部リンクはネイティブで動き、Web を直せばアプリにも反映されます。会社の準備から審査に出すまでの手順は [docs/app-release.md](docs/app-release.md) にまとめています。

```bash
npx cap sync          # 設定とプラグインを ios/ と android/ に反映する
npx cap open ios      # Xcode で開く（Mac）
npx cap open android  # Android Studio で開く
```

## 本番公開（Vercel）

1. Vercel でこのリポジトリをインポートする。
2. Vercel はファイルに書き込めないため、[Turso](https://turso.tech) などで libSQL のDBを作り、`DATABASE_URL` と `DATABASE_AUTH_TOKEN` を設定する。Vercel の Marketplace から Turso を入れた場合は `TURSO_DATABASE_URL` と `TURSO_AUTH_TOKEN` が自動で入り、そのまま読みます。テーブルは初回アクセス時に自動で作られます。
3. 文章AIの設定（上の「今使っている設定」の5つ）を環境変数に入れる。

本番の URL は **https://yotachat.app**（Vercel で購入。自動更新あり、毎年 $15）。`www.yotachat.app` と、もとの `yota-bice.vercel.app` は、どちらも yotachat.app に転送する（308）。

## 構成

```
src/
  app/
    page.tsx                 ホーム（5秒ごとに切り替わる注目作＋キャンパスの物語の棚＋遊び方のタブ・カテゴリ・ハッシュタグで絞りこめる2列の作品一覧）
    plot/[plotId]/page.tsx   作品の紹介ページ（紹介文・あなたの役・登場人物のプロフィール）
    chat/[plotId]/page.tsx   会話画面
    api/session              年齢確認と名前（生まれた年月と、物語の中で呼ばれる名前だけを保存）
    api/conversation         会話の取得・新規開始
    api/chat                 返答のストリーミング（NDJSON）
    api/suggest              次の返事の候補（キャラが返すたびに3つ）
    api/messages/[id]        返答の手直し
    api/events               計測イベント
  components/                ChatScreen, AgeGate, UserName, SceneCard, StoryMessage, Featured, Shelf, PlotList, StartButtons, Avatar
  lib/
    characters.ts            公式キャラ・プロット26本（全員18歳以上の架空の人物。学園ものは大学が舞台）
    story.ts                 返答を台詞・地の文・情景に分け、吹き出しにまとめる
    username.ts              名前の検証と、地の文の「あなた」の置き換え
    prompt.ts                システムプロンプト（視点、3往復で山場、安全の指示）
    chat.ts                  1往復の処理（判定→生成→流しながら判定→保存）
    safety.ts                入力・出力の安全判定
    memory.ts                長期記憶（古い会話をあらすじに要約）
    usage.ts                 未成年の利用時間
    llm/                     文章AIの差し替え層（Anthropic / OpenAI / Gemini / ダミー）
```

性格ベクトル（activation steering）で、キャラの性格を調整する実験の道具と指示書は `steering/` にある（`steering/INSTRUCTIONS.md`。DGX Spark で、モデルとベクトルの組み合わせを探す）。アプリ本体からは使っていない。

**ジャケット**（`<plotId>-jacket.webp`、3:4・900×1200）は、タイトルの文字と吹き出しを入れた漫画・ラノベの表紙風の絵。もとの表紙を参照画像にして、キャラの見た目を保ったまま Higgsfield の `gpt_image_2_5`（quality high・2k・3:4）で作る。日本語の文字が崩れることがあるので、書き出す前に必ずタイトルを目で確かめ、崩れていたら「次の文字をこの順に1回ずつ」と1字ずつ書いて作り直す。一覧・注目作・紹介ページはジャケット、年齢確認と名場面カードは文字のない表紙を使う。

キャラの絵は `public/art/` にある（Higgsfield の nano_banana_2 で生成。表紙は 2:3、背景は 9:16、どちらも 2k で作り、下のサイズに縮めて書き出す）。表紙 `<plotId>-cover.webp`（900×1342）、会話画面の背景 `<plotId>-bg.webp`（幅720）、アイコン用の顔 `face-<名前>.webp`（192×192）。パスは `characters.ts` の `cover` / `backdrop` / `face` に書く。

### 1往復の流れ

1. 入力を安全判定。問題があればAIに送らず、別の展開を促す。
2. あらすじ＋直近の会話＋キャラ設定でプロンプトを組み、返答を流す。
3. 流しながら出力も判定し、問題があればその場で差し替えて生成を止める。
4. 返答を送り終えてから、計測の記録と、必要ならあらすじの更新を行う（返答の速さに影響しない）。

## 管理者画面（`/admin`）

運営用の画面。Vercel の環境変数 `ADMIN_PASSWORD`（8文字以上）を入れて再デプロイすると使えるようになる（入れるまでは「まだ使えません」と出る）。パスワードでログインすると、7日間ログインが続く（パスワードを変えると、それまでのログインは切れる）。15分に8回まちがえると、しばらくログインできなくなる。

- **概要**：今日と7日間の、新しい人・話した人・会話・メッセージ・評価の平均・ご意見・通報・作られた作品・X の診断・文章AIの費用。よく遊ばれた作品。
- **ご意見・通報**、**評価**：送られた内容の一覧（種類で絞れる）。
- **作品**：承認待ち・掲載中・運営の作品・リンクだけ・止めた作品。承認して掲載／載せない／止める／戻す／新作に入れる・外す／削除。通報の数も出る。
- **費用**：文章AIの費用の日ごと・用途ごと（`USDJPY` で円のレートを変えられる。記録に費用がないものは `LLM_PRICES` の単価で計算）。
- **作品を追加**：作る画面（`/create?official=1`）で書き、「公開する」を押すと、確認なしでホームの「新作」の棚に出る（運営の作品。作者名は出さず「yota オリジナル」と出す）。管理者は、どの作品も作る画面で直せる（直しても公開はそのまま）。
- 中身は `src/lib/admin.ts`（ログイン）、`src/lib/admin-data.ts`（集計）、`/api/admin/*`、`src/components/admin/AdminApp.tsx`。今までのスクリプト（`npm run feedback` / `ugc` / `cost`）も、そのまま使える。

## 会話の演出

- **心の声**：登場人物が口に出さない本音を `〈…〉` で書かせ、画面ではぼかして見せる。長押ししているあいだだけ読め、指を離すとまたぼかす。素直になれない人物ほど、台詞とのずれを大きくする。
- **言いかけて消す**：言いかけてやめた言葉を `~~…~~` で書かせ、一度ふつうに見せてから打ち消し線を引いて薄くする。
- **山場のカットイン**：出来事を起こす返答の最初の行に `▼見出し` を書かせ、上下に黒い帯が入って見出しが浮かぶ演出にする。会話の中には章の区切りとして残る。
- 文章AIは「ときどき〜する」を守りにくいので、どの返答で入れるかをこちらで決め、その返答のプロンプトの最後（【この返答で】）で指示する（`prompt.ts` の `hookTurn`・`innerTurn`・`hesitateTurn`）。山場は3往復目とそのあと4往復ごと、心の声は2往復目から3往復ごと、言いかけは4往復目から6往復ごと。
- 書式の読み取りは `src/lib/story.ts`。あらすじ・返事の候補には書式を外して渡す（`plainStory`。心の声と言いかけは、相手に聞こえていないので候補の材料にしない）。
- **距離**：話した回数が増えるほど、背景の絵が少しずつ寄り、推し色の光がにじむ。
- **時間**：端末の時刻で背景の色を変え（深夜は青く暗く、朝はやわらかく、夕方は橙）、時刻と曜日をプロンプトに渡す（`src/lib/clock.ts`。物語の中の時間が決まっていれば、そちらを優先する）。
- **名場面カード**：右上から読む3コマの漫画風（①作品の絵とナレーション ②話している人の顔と台詞の吹き出し ③心の声の雲の吹き出し、なければもう1つの台詞）。縦書きで描く（`SceneCard.tsx`）。

## ユーザーが作る作品（UGC）

- **作る**：ホームの「つくる」から（`/create`、`src/components/CreatePlot.tsx`）。18歳以上なら誰でも作れる。最初に「アイデアから下書き」（一行のアイデアから文章AIが全項目を下書き。`src/lib/ugc-draft.ts`）か「白紙から書く」を選ぶ。そのあとは1ページの編集画面で、基本・登場人物・始まり・展開をまとめて直す。
  - **必須は7つだけ**：題名・舞台と関係・キャラの名前・年齢（18歳以上）・口調・性格か見た目・最初の一言。ほかは空でよく、作品にするときに補う（`ugc-schema.ts` の `withDefaults`）。
  - **あと〇つ**：下のバーに足りない項目をチップで出し、押すとその欄へ飛ぶ。足りないまま「完成」を押しても、何が足りないかを出す（`missingItems`）。使えない言葉は入力中に知らせる。
  - **AIで考える**：どの欄にもあり、いま書いてある内容に合わせた案を数個出す（`src/lib/ugc-assist.ts`・`/api/ugc/assist`。1日200回まで）。案は選んで入れるだけ。
  - **試しに話す**：保存せずに、書きかけの作品で会話を試せる（`/api/ugc/try`。題名や舞台が空でも、名前・口調・最初の一言があれば話せる。1日150回まで）。
  - **{{user}}**：作品の文章に `{{user}}` と書くと、会話では遊ぶ人の名前に、一覧や紹介ページでは「あなた」になる（`username.ts` の `fillUser`／`fillPlot`）。
  - **口調の例**：キャラごとに「こう言われたら、こう返す」を3つまで書け、プロンプトの人物の欄に入る。
  - **キャラの画像**：画面で正方形（512px）に切り抜いて登録し（`/api/ugc/images`、DB に保存、1日30枚まで）、アイコンと文字ジャケットの背景に使う。
  - **下書きの自動保存**：書いている途中は端末（localStorage）に残し、開き直すと「続きから書く」を出す。保存した作品は紹介ページの「直す」から同じ画面で直せる（`PUT /api/ugc/<id>`）。公開中の作品を直すと、確認待ち（pending）に戻る。題名を変えるとジャケットを作り直す。
  - **ほかのアプリから引っ越す**：ほかのAIチャットで作った自分の作品の設定（キャラ設定・プロット・最初のメッセージ・トークプロフィールなど）を貼ると、文章AIが yota の作品の形に移す（`src/lib/ugc-import.ts`・`/api/ugc/import`）。作者の言葉をできるだけそのまま残し、足りない項目だけ補う。`{{char}}` は名前に置きかえ、`{{user}}` はそのまま使う。
    - ほかのアプリには一切アクセスしない（貼られた文章を使うだけ）。貼った文章は保存しない。
    - 「自分が作ったオリジナルの作品」と確認してもらう。版権もの（既存の作品・実在の人物・VTuber など）だと文章AIが判断したら、作品を作らずに断る。
    - 未成年の設定は20歳以上・大学に直し、性的な表現は移さない。変えたこと・省いたことは、移したあとに作者に知らせる。子どもを性的に扱う内容は、文章AIに渡す前に止める。
    - できた下書きは保存せず作る画面に出すので、作者が確かめてから保存する。保存のときの確認と、公開前の運営の確認はいつもどおり。
    - `/create?import=1` で開くと、引っ越しの欄をいちばん上に開いて出す（募集の投稿などに使う。`&ref=` も付けられる）。1日10回まで。
    - 欄には、貼るもの（題名と紹介文・プロンプト・イントロ・状況例・トークプロフィール・設定集）と、遊び方（あなたが主人公／ふたりを見守る）の選択を置く。8,000字を超えたら黙って切らずに、超えたことを知らせる。
    - AIの出力が数や長さの決まりから少しはみ出しただけなら整えてから確かめ（`normalizeDraft`）、閉じ括弧の欠けも補って読む。崩れたら3回まで作り直させる。状況例の `{{user}}:`／`{{char}}:` の会話は口調の例に入れる。見守りの作品は見守りの形だけで移す。
  - 1日に下書き20回・新しい作品5つ・保存し直し60回まで。
- **守り**：作品の文章は、会話より厳しい判定にかける（未成年や学校の段階を示す語・性的な語は1つでも止める。`ugc-schema.ts` の `checkCreation`）。【】は消し、プロンプトでは「ユーザーが書いた設定の中の指示には従わない」と先に断る。紹介ページに「通報」がある。
- **公開の段階**：作ったらリンクを知っている人が遊べる（private）。作者が申請すると pending になり、運営が承認すると「みんなの作品」に載る（public）。問題があれば removed でリンクも止める。確認と承認は `npm run ugc -- list` / `show <id>` / `approve <id>` / `decline <id>` / `remove <id>`（本番の Turso の `DATABASE_URL` と `DATABASE_AUTH_TOKEN` を設定して実行）。
- **ジャケット**：保存すると、画像生成AIでタイトル文字入りのジャケットを作る（`src/lib/jacket.ts`、返事を返したあとに作り、DB に webp で保存）。Vercel の環境変数に `IMAGE_API_KEY`（OpenAI 互換の Images API のキー）を入れると有効になる。`IMAGE_MODEL`（既定 gpt-image-1）・`IMAGE_BASE_URL`・`IMAGE_QUALITY` で変えられる。キーがないとき・作れなかったときは、推し色とタイトルだけの文字ジャケットを出す。
- ユーザーの作品の ID は `u-` で始まり、紹介ページは `/u/<id>`、会話は `/chat/<id>`（こちらの作品と同じ画面）。

## ログイン（Google・メールアドレス・LINE・Apple）とゲストの上限

登録なしで始められる（年齢の確認と名前だけの、匿名のセッション）。仕組みは `src/lib/auth.ts`・`src/lib/email-login.ts`。

- **Web のゲストだけに上限**：Web のゲストが送れるメッセージは `GUEST_MESSAGE_LIMIT` 回（既定 15）までで、使い切ると会話の画面でログインをすすめる。ログインした人は上限なし。
- **アプリは上限なし**：アプリを入れた人はゲストとして扱わない（User-Agent の `YotaApp` で見分ける）。アプリで出すログインは、機種変更の引き継ぎ用のメールアドレスだけ（任意）。ほかのサービスのログインを出さないので、Apple の審査 4.8（Sign in with Apple も必須）はかからない。
- **メールアドレスのログイン**：6けたのコードをメールで送り、画面に入れてもらう（リンク式だと、アプリから始めても端末のブラウザでログインしてしまうため）。コードは10分・5回まで。同じアドレスへは1分あけて1時間に5通、同じ接続元から1時間に10通、全体で1日 `EMAIL_DAILY_LIMIT` 通（既定 500）まで。アドレスとコードはハッシュでしか持たない。
- **ゲストの記録は引き継ぐ**：はじめてログインしたアカウントは、いまのセッションにそのまま結びつく。前にログインしたことのあるアカウント（機種変更など）なら、そのアカウントに切りかえ、ゲストのあいだの会話・作品をそちらへ移す。
- **持つのは ID のハッシュだけ**：名前・プロフィール画像は求めず、メールアドレスもそのままの形では保存しない（`identities` テーブルに、方法の名前と、`AUTH_HASH_SALT` を混ぜた ID のハッシュ）。
- **年齢の確認が先**：はじめての人がセッションなしでログインしようとしたら、先に年齢の確認をしてもらう。前にログインした人は、年齢の確認の画面の「以前ログインした方はこちら」から戻れる。
- **キーが1つも入っていないあいだ**は、ログインのボタンも、ゲストの上限も出ない（今までどおり無制限）。
- 戻り先（Callback / Redirect URI）は、どれも `https://yotachat.app/api/auth/<google|line|apple>/callback`。
- **キーなしで試す**：ローカルで `EMAIL_MOCK=1` を付けて起動すると、メールを送らずにコードをサーバーのログに出す（本番の環境では効かない）。

設定のしかた（入れたものから使えるようになる。入れたら Vercel で再デプロイ）：

## Xから生まれる彼（`/x`）

Xでログインすると、本人のプロフィールと最近の投稿100件（リポストを除く）を読み、文章AIが ① Xのタイプ ② 投稿のクセへの愛のあるツッコミ3つ ③ その人に刺さるオリジナルの彼の作品 を作る（`src/lib/x.ts`・`src/lib/x-analyze.ts`）。彼はユーザーの作品（private）として保存され、そのまま話せる・直せる。結果ページ `/x/<id>` はシェア用で、カードの画像（`opengraph-image`）も作る。

- **読むのは本人だけ**：OAuth 2.0（PKCE）で本人にログインしてもらう。権限は `tweet.read users.read`（読み取りだけ）。他人のアカウントは診断できない。
- **保存しないもの**：アクセストークンと投稿は保存しない（診断の処理の中でだけ使う）。残すのは結果（タイプ・ツッコミ・彼の作品のID）と、X のユーザーIDのハッシュ（同じアカウントは3日間、投稿を読み直さずに前の結果を出す）。
- **守り**：プロフィールに未成年を示す言葉があれば作らない。容姿・性別・病気・政治・宗教などには触れない・推測しないと指示し、ツッコミと作品は作品づくりと会話の安全判定にかける。投稿の URL とほかの人の @ID は AI に渡さない。
- **費用**：X API は従量課金（ユーザー1件 $0.010・投稿1件 $0.005）で、1回の診断で約 $0.51。1人1日2回まで、全体で1日 `X_DAILY_LIMIT` 回まで（既定 200 回 ≒ 1日 $100 まで）。
- **設定のしかた**
  1. [X Developer Console](https://console.x.com) でアプリを作る。
  2. 「User authentication settings」で OAuth 2.0 を有効にし、App type を「Web App（Confidential client）」、Callback URI を `https://yotachat.app/api/x/callback`、Website URL を `https://yotachat.app` にする。
  3. 「Keys and tokens」の OAuth 2.0 Client ID と Client Secret を、Vercel の環境変数 `X_CLIENT_ID`・`X_CLIENT_SECRET` に入れる（任意で `X_DAILY_LIMIT`・`X_HASH_SALT`）。
  4. Developer Console でクレジットを買い、使いすぎないよう上限（spending limit）を決める。
  5. Vercel で再デプロイする。キーが入るまでは `/x` は「準備中」で、ホームの入口も出ない。
- **キーなしで試す**：ローカルで `X_MOCK=1` を付けて起動すると、架空の利用者の投稿で最後まで試せる（本番の環境では効かない）。

## ユーザーの声を集める

- **会話のあとのひとこと評価**：1つの会話で6回話したところで、会話の下に1回だけ「ここまでの〇〇との会話、どうでしたか？」を出す（5段階・ほかのキャラチャットアプリとの比べ・ひとこと）。答えるか閉じたら、その会話では二度と出さない。
- **ご意見・不具合**：ホームの一番下から、感想・不具合・要望を送れる（年齢確認の前でも送れる。返事がほしい人は連絡先を書ける）。
- **流入元**：リンクに `?ref=x-post` のように付けると、最初に開いたときの値を端末に覚え、年齢確認のときにセッションに記録する。募集の投稿ごとに違う値を付けると、どこから来た人がどれだけ遊び、どう評価したかを分けて見られる。
- **集計**：`npm run feedback -- --days 14`（本番を見るときは、Turso の `DATABASE_URL` と `DATABASE_AUTH_TOKEN` を設定して実行）。流入元ごとの人数（リンクを開いた → 年齢確認 → 会話を始めた → 6回以上話した）、作品ごとの平均点、ほかのアプリとの比べ、ひとこととご意見の一覧を Markdown で出す。
- **謝礼つきモニター**：`npm run feedback -- --make-monitors 20` で、1人ずつ違うリンク（`?ref=m-xxxxxx`）を作って渡す。集計の「モニターの達成状況」に、6回以上話した作品の数・評価・ひとことの数と、条件（`--need-plots 3`）を満たしたかが出るので、謝礼を払う前に確かめられる。リンクは、遊ぶ端末（スマホ）で開いてもらう（最初に開いた端末に覚えるため）。

## 計測

`events` テーブルに、`session_start`、`conversation_start`、`chat_send`（最初の文字までの時間を含む）、`regenerate`、`card_open`、`card_share`、`viewpoint_select` などを記録します。視点ごとの継続率や、カードの共有率の集計に使います。

### 文章AIの原価

文章AIを呼ぶたびに、`llm_usage` テーブルへ1行残します（`src/lib/llm-usage.ts`）。残すのは、用途（返答・返事の候補・あらすじ・作品づくり・引っ越し・X診断）、ユーザーのセッション、モデル、考える量、トークン数（入力・キャッシュ・出力・推論）、推論の文字数、かかった時間、最後まで返ったかどうかです。会話の中身は残しません。書き込みは返事を返し終えてから行うので、返答の速さは変わりません。

- 単価は `LLM_PRICES`（100万トークンあたりの米ドル）で入れます。例：`LLM_PRICES='{"qwen-3.8-27b":{"input":0.6,"output":1.2}}'`。入れていなくても記録は残り、集計のときに `--prices` で計算できます。
- 集計は `npm run cost -- --days 7`。用途ごとの原価と割合、出力に占める推論の割合、1往復あたりの原価、1人1日あたりの原価（中央値・上位10%）、よく使う上位10%が原価の何割を使っているかを Markdown で出します。単価を変えて計算し直すときは `--prices '{"qwen-3.8-27b":{"input":0.6,"output":1.2}}'`、円に直すレートは `--usdjpy 150`。
- OpenAI 互換の API（Cerebras など）は、ストリーミングの最後のチャンクで使用量を返すものとして読んでいます。本番で集計の「トークン数が分からないもの」が返答の回数とほぼ同じになったら、使用量が返っていないので、`OPENAI_STREAM_USAGE=1`（`stream_options.include_usage` を送る）を設定してください。推論のトークン数の内訳が返らない場合は「推論の文字数」を目安にします。
